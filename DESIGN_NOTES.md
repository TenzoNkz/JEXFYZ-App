### Owner revision — per-second statistics only during cooler operation (2026-11-10)

**Owner requirement:** remove the selectable wall-clock periods `1H / 24H / 7D / 30D`. Usage Statistics must be based on per-second samples during real cooler operation, not an always-running app/BLE connection window.

- **Chart/session model:** use one cooling-operation session at a time. Begin only after full P1 synchronization when authoritative Firmware output telemetry confirms the cooler is active. End the session when both physical outputs are confirmed OFF, BLE/P1 is disconnected or session freshness is lost. If the cooler turns OFF then ON again, create a new session; off-time is never counted or charted. Preserve completed per-run history in local SQLite so the previous run can still be inspected after OFF.
- **Active-output definition (recommended, based on existing Firmware contract):** cooler is active when `FAN == ON` OR `PELTIER == ON`, using authoritative telemetry only. This includes a fan-only thermal-protection/cool-down interval where Firmware has deliberately shut the Peltier OFF but continues Fan 100%. When both outputs are OFF, the cooler is inactive. `ADAPTIVE == ON`, BLE connected, stored settings, command intent or ACK alone must not start a statistics session.
- **Per-second samples:** record Phone Battery and Hotside temperature observations at 1 Hz while the active session is open. Persist timestamped per-second samples (with `null`/explicit gaps when that sensor has no fresh valid sample); do not merely update freshness and store temperature rows only when the value changes. Keep physical-state changes such as Voltage, Adaptive and Fan Speed as authoritative event/step transitions on the same elapsed-seconds axis rather than writing redundant identical state rows every second.
- **Time axis and summary:** replace the 1H/24H/7D/30D selector with elapsed time since the actual cooling session began (`00:00:01`, `00:00:02`, …, with readable automatic `mm:ss` / `hh:mm:ss` labels for long runs). Temperature plots and operating-profile lanes must use the same elapsed active-session axis. Summary durations count only active seconds; OFF/idle/disconnected time contributes zero.
- **Data truth:** use P1 `HOT` heartbeat and the existing Android phone-battery reader; no interpolation across stale/missing readings, reconnect boundaries or OFF periods. Keep `--`/gaps for unavailable sensors. Do not derive physical ON from an ACK or the selected mode.
- **Storage/architecture:** current App-local SQLite storage remains the owner; no Firmware timer, NVS time-series, Firebase or cloud upload. Add a versioned SQLite migration for per-second sample storage if needed. The existing 30-day pruning is an internal retention policy, not a selectable 30D chart range; validate database growth under realistic active runtime before setting a long-term capacity claim.
- **Current source evidence:** `lib/usage_statistics.dart` blob `eb548c65453940a8b52a570477180ff860b78c02` still exposes `UsagePeriod.hour/day/week/month`, filters a rolling wall-clock period and stores temperature events only when the value changes (while touching freshness each receipt). `lib/main.dart` blob `f4c813f4a34a8d806168de1becedba95261c2479` starts the statistics session after P1 synchronization regardless of output state and ends it on BLE disconnect. Firmware V7.1 authoritative paired `FAN`/`PELTIER` outputs are published separately; `TOUCH_COOLING` toggles both, while safety can intentionally leave Fan on with Peltier off.
- **Required regression tests:** connected but both outputs OFF records nothing; SYNC with FAN ON or PELTIER ON starts one session; fan-only safety operation remains counted; both outputs OFF closes it; reconnect with fresh sync + active output starts a new session; no time accrues while OFF/disconnected; every active second has correctly timestamped fresh values or an explicit gap; no stale carry-forward; history selection shows completed sessions without 1H/24H/7D/30D choices. Preserve current 350/420-dp, Default hybrid/Light/Dark, EN/ID and storage-error coverage.

## Home status icon contract

- Unknown/disconnected state must never fabricate values or imply output ON/OFF. Preserve semantic accent at rest; stop and reset state-driven animations while disconnected.
- Battery: Ice Blue at/below 30°C, smooth transition through cyan/amber/orange from 30–40°C, red/fire effect at or above 40°C. Falling oval embers with warm yellow-white cores, soft restrained halo and deterministic phases are behind the shell and clipped inside the rounded frame but outside the foreground icon.
- Hotside: Ice Blue at/below 30°C, smooth transition to red/flame at the configured Hotside limit. Embers are background-only, clipped outside the raised thermometer silhouette; tube, bulb and graduations paint above particles. UI effect never modifies Firmware safety.
- Voltage: bolt face/core remains static. Two pulses travel along the closed outer contour. No moving central spine or internal strikes; no white pixels may leak beyond the bolt silhouette. Keep 5V/9V/12V red/green/blue and 25%/50%/100% visual intensity mapping.
- Adaptive: exactly two directional arcs/arrowheads with restrained halo/highlight; no orbiting dot or unrelated particles.
- Peltier: one six-branch rotating snow crystal and recognisable flakes behind it. Frost/snow strength maps to 5V/9V/12V classes; no random dots or orbiting sparks.
- Fan: one five-blade swept rotor and layered hub; exactly three curved airflow ribbons remain fixed behind the blades. Only rotor angular speed changes by voltage/PWM class. Airflow fades only during the permitted one-shot connected ON→OFF coast, then Fan is static.
- Fan Speed: fixed upper-half semicircle gauge, start π and sweep π. Known OFF puts the needle at far-left; proportional PWM reaches far-right at 100%. Retarget from authoritative state without autonomous phase loop/wobble. Hide the needle for unknown/disconnected PWM instead of implying OFF.
- Animation gate: while BLE disconnected, stop/reset all custom icon controllers. While connected, Battery/Hotside/Voltage loop continuously even if the sensor value is unknown (value remains --). Adaptive/Peltier/Fan/LED animate only when authoritative state is ON; OFF is static, except the connected Fan's one-shot coast. Bluetooth icon is static.
- Keep animations phase-compatible at loop seams. Effects must not fabricate sensor values, voltage, current, output state or physical RPM.
